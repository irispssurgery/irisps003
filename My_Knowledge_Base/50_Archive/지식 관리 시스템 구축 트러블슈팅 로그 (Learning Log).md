# 📝 지식 관리 시스템 구축 트러블슈팅 로그 (Learning Log)

**작성일:** 2024년 5월 22일
**주제:** PowerShell 기반 폴더 자동화 시스템 구축 및 오류 복구 과정

## 1. 프로젝트 목표 (Objective)
- 분류 체계(Inbox, Processing, Archive, Projects)를 가진 자동화된 폴더 구조 생성.
- 각 폴더의 용도와 규칙을 담은 가이드 문서(`gemma4.md`) 자동 생성.
- 한글 깨짐 없는 안정적인 인코딩(UTF-8) 환경 구축.

## 2. 발생한 오류 및 해결 과정 (Error & Resolution)

### ❌ 오류 1: 경로 생성 시 문자열 오타 발생 (Path Corruption)
* **현상:** `New-Item` 또는 `Out-File` 실행 시 `Could not find a part of the path '...\\ChildPath\\README.md'`라는 에러 발생.
* **원인 분석 (Root Cause):** 
    - `Join-Path` 명령어를 사용하면서 `-ChildPath`라는 매개변수 이름을 경로의 일부로 오인하여 코드에 잘못 삽입함.
    - 결과적으로 존재하지 않는 `ChildPath`라는 가상의 폴더를 찾으려다 경로 끊김 현상 발생.
* **해결 방법 (Resolution):** 
    - `Join-Path`의 매개변수 구조를 재검토하여 오타 제거.
    - `$basePath`와 `$task.Path`를 결합할 때 가장 단순하고 안전한 방식으로 로직을 수정.

### ❌ 오류 2: 폴더 구조 중복 및 꼬임 (Directory Mess)
* **현상:** 스크립트 오류로 인해 의도치 않은 이름의 폴더(예: `ChildPath`가 포함된 경로)가 생성되거나, 폴더 구조가 중첩됨.
* **원인 분석 (Root Cause):** 
    - 잘못된 경로 생성 로직이 반복 실행되면서 물리적인 디렉토리 구조가 논리적 설계와 어긋남.
* **해결 방법 (Resolution):** 
    - **1단계 (수동):** 사용자에게 수동 삭제를 안내하여 가장 안전하게 오염된 폴더를 제거하도록 함.
    - **2단계 (자동):** `Test-Path`를 사용하여 폴더 존재 여부를 먼저 확인하고, 이미 있는 경우 덮어쓰지 않고 건너뛰는 '방어적 프로그래밍(Defensive Programming)' 로직 적용.

### ❌ 오류 3: 한글 인코딩 깨짐 (Encoding Issue)
* **현상:** 생성된 `.md` 파일 내의 한글이 깨져서 읽을 수 없음.
* **원인 분석 (Root Cause):** 
    - PowerShell의 기본 인코딩 설정이 시스템 환경에 따라 `UTF-16` 또는 `ANSI`로 되어 있어, 현대적인 `UTF-8` 표준과 충돌.
* **해결 방법 (Resolution):** 
    - `Out-File` 명령어에 `-Encoding utf8` 옵션을 명시적으로 지정하여 모든 환경에서 동일한 인코딩 결과가 나오도록 강제함.

## 3. 핵심 학습 교훈 (Key Takeaways)

1.  **경로 결합의 원칙 (Path Safety):** 
    - 경로를 문자열 더하기(`$a + "\\" + $b`)로 만들지 말고, 반드시 `Join-Path`를 사용하라. 이는 슬래시(`/`)나 역슬래시(`\`) 누락 문제를 방지한다.
2.  **멱등성(Idempotency) 확보:** 
    - 스크립트는 여러 번 실행해도 결과가 같아야 한다. "폴더가 이미 있으면 생성하지 않는다"와 같은 예외 처리가 필수적이다.
3.  **로그 및 에러 처리의 중요성:** 
    - 작업 전 `Write-Host`나 `Write-Debug`를 통해 현재 어떤 경로에 작업을 수행 중인지 명시하는 습관이 디버깅 시간을 단축시킨다.
4.  **검증된 코드의 힘:** 
    - 복잡한 로직을 짤 때는 한 번에 다 짜지 말고, 가장 작은 단위(파일 생성 -> 폴더 생성 -> 내용 작성)부터 테스트하며 확장해야 한다.

## 📌 Brief Summary

PowerShell을 활용한 지식 관리 시스템(PKM) 폴더 구조 자동화 및 가이드 문서 생성 과정에서 발생한 기술적 오류와 그 해결책을 정리한 문서입니다. 안정적인 인코딩 환경 구축과 방어적 프로그래밍 로직 적용을 통해 자동화 스크립트의 신뢰성을 확보하는 과정을 담고 있습니다.

## 📖 Core Content

자동화 시스템 구축 중 발생한 주요 오류와 이를 극복하기 위한 핵심 전략은 다음과 같습니다.

### 1. 주요 오류 및 해결 사례 (Error & Resolution)

- **경로 생성 및 오타 문제 (Path Corruption)**:
    
    - **현상**: `Join-Path` 사용 시 매개변수 이름을 경로 일부로 오인하여 잘못된 경로를 참조하는 오류가 발생했습니다.
        
    - **해결**: 매개변수 구조를 재검토하고 `$basePath`와 작업 경로를 결합하는 로직을 가장 단순하고 안전한 방식으로 수정했습니다.
        
- **폴더 구조 오염 (Directory Mess)**:
    
    - **현상**: 잘못된 경로 로직의 반복 실행으로 논리적 설계와 어긋난 중첩 폴더들이 생성되었습니다.
        
    - **해결**: 오염된 폴더를 수동으로 제거한 후, `Test-Path`를 활용해 기존 폴더 존재 여부를 확인하고 중복 생성을 방지하는 **방어적 프로그래밍**을 적용했습니다.
        
- **한글 인코딩 충돌 (Encoding Issue)**:
    
    - **현상**: 시스템 기본 인코딩(UTF-16/ANSI) 차이로 인해 마크다운 파일 내 한글이 깨지는 현상이 발생했습니다.
        
    - **해결**: `Out-File` 명령어에 `-Encoding utf8` 옵션을 명시적으로 지정하여 인코딩 표준을 강제했습니다.
        

### 2. 핵심 기술적 교훈 (Key Takeaways)

- **경로 안전성 (Path Safety)**: 슬래시 누락 방지를 위해 문자열 결합 대신 반드시 `Join-Path`를 사용해야 합니다.
    
- **멱등성(Idempotency) 확보**: 여러 번 실행해도 결과가 동일하도록 예외 처리를 필수적으로 포함해야 합니다.
    
- **단계적 확장**: 복잡한 로직을 한 번에 구현하기보다 파일 생성, 폴더 생성, 내용 작성 등 최소 단위부터 테스트하며 확장하는 것이 효율적입니다.
