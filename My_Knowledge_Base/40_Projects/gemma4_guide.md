# 🚀 [SOP] Projects 작업 지침
## 🎯 목표: 계획을 실행으로 옮겨 가시적인 결과물을 만들어내기

## 📌 이 폴더의 성격
- **Action-Oriented**: 단순히 읽는 것이 아니라, '수행'하는 공간입니다.
- **Time-Bound**: 모든 프로젝트에는 시작일과 종료일(Deadline)이 있습니다.
로
## ✅ 수행 작업 (To-Do)
1. **Setup**: 프로젝트의 목표(Goal)와 마감 기한을 명시한 'Project Charter'를 작성합니다.
2. **Breakdown**: 큰 목표를 작은 단위의 실행 가능한 태스크(Sub-tasks)로 쪼갭니다.
3. **Execute**: `30_Permanent`에 저장된 지식을 활용하여 실제 작업을 수행합니다.
4. **Track**: 진행 상황(Status: TODO -> IN_PROGRESS -> DONE)을 주기적으로 업데이트합니다.
5. **Complete**: 프로젝트가 완료되면 결과물을 정리하여 `50_Archive`로 이동시킵니다.

## 🛠 작업 도구 및 규칙
- **Rule 1**: 완료되지 않은 프로젝트를 무한정 늘리지 마세요. (한 번에 3개 이하 권장)
- **Rule 2**: 매일 혹은 매주 최소 하나의 태스크는 'DONE' 상태로 만드세요.
- **Rule 3**: 결과물(Output)이 나오면 반드시 기록으로 남겨 `30_Permanent`로 환류시킵니다.

## 🔗 연결된 흐름
- **Input**: [[30_Permanent]]의 지식을 재료로 사용.
- **Output**: 완료 후 [[50_Archive]]로 이동.

# [[Projects 폴더 작업 지침 (SOP)]]

## 📌 Brief Summary

Projects 폴더는 수집된 지식을 바탕으로 구체적인 계획을 실행에 옮겨 가시적인 결과물을 도출하는 액션 중심의 공간입니다. 모든 작업은 명확한 마감 기한(Deadline)을 가지며, 목표 지향적인 태스크 수행을 원칙으로 합니다.

## 📖 Core Content

프로젝트의 성공적인 완수를 위해 다음과 같은 단계별 표준 운영 절차(SOP)를 따릅니다.

- **수행 단계 (Workflow)**:
    
    - **Setup**: 프로젝트 목표와 마감 기한을 명시한 'Project Charter'를 작성하여 방향성을 설정합니다.
        
    - **Breakdown**: 거대한 목표를 즉시 실행 가능한 작은 단위의 태스크(Sub-tasks)로 세분화합니다.
        
    - **Execute**: `30_Permanent`에 저장된 축적된 지식을 재료로 삼아 실제 작업을 수행합니다.
        
    - **Track**: 작업 상태를 `TODO` → `IN_PROGRESS` → `DONE` 단계로 주기적으로 업데이트하며 관리합니다.
        
    - **Complete**: 완료된 프로젝트 결과물을 정리한 후 `50_Archive`로 이동시켜 기록을 보존합니다.
        
- **운영 원칙 및 도구**:
    
    - **집중**: 동시 진행 프로젝트를 3개 이하로 제한하여 실행력을 높입니다.
        
    - **지속성**: 최소 주 1회 이상 태스크를 'DONE' 상태로 전환하여 추진력을 유지합니다.
        
    - **환류**: 도출된 결과물과 지식은 다시 `30_Permanent`에 기록하여 지식 자산을 확장합니다.
